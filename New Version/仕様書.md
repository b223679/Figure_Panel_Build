# Fiji Figure Panel Builder Plugin 仕様書

## 1. 目的

Fiji/ImageJ上で、複数のTIF画像を行列状に配置し、論文・学会発表用の顕微鏡画像パネルを簡単に作成するプラグインを開発する。

主な用途は以下。

- 複数conditionの顕微鏡画像の比較
- 各channelの単独表示
- 複数channelのMerge表示
- condition × channel のfigure作成
- 全画像に共通したBrightness & Contrast設定
- LUT設定
- 行・列ラベル追加
- スケールバー追加
- 最終画像をTIFとして保存

例：

                Condition 1   Condition 2   Condition 3
Channel 1
Channel 2
Merge

または

                Channel 1    Channel 2     Merge
Condition 1
Condition 2
Condition 3

のような配置を作れるようにする。


# 2. 開発環境

Fiji/ImageJ用プラグインとして実装する。

推奨：

- Java
- ImageJ2 / SciJava Plugin framework
- Maven project
- Fiji上で動作
- GUIはSwingまたはSciJava UI
- 画像処理にはImageJ APIを使用

複雑なレイアウト編集を行うため、
GenericDialogだけではなくSwingベースのカスタムGUIを推奨する。

Windows版Fijiでの動作を必須とする。


# 3. 入出力

## 3.1 入力

入力形式：

- `.tif`
- `.tiff`

複数ファイルを同時選択可能。

ImageJ/Fijiで開いている画像から選択する方法と、
ファイル選択ダイアログから読み込む方法の両方を用意するのが望ましい。

入力画像は以下を想定する。

- grayscale TIF
- multi-channel TIF
- ImageJ hyperstack TIF

各画像について取得する情報：

- filename
- width
- height
- number of channels
- bit depth
- pixel calibration
- channel name（存在する場合）
- LUT情報


## 3.2 出力

出力形式：

- TIFF

保存時：

`File > Save As`

相当のダイアログを表示する。

出力画像はRGB TIFFをデフォルトとする。

理由：
LUT、Merge、ラベル、スケールバーを最終figureとして固定するため。

オプションとして、

- RGB TIFF
- 元bit depthを可能な限り維持

を選択可能としてもよいが、v1ではRGB TIFFのみでもよい。

# 5. Grid設定

## 5.1 行列数

ユーザーが以下を入力できる。

- Number of rows
- Number of columns

整数入力。

最低値：

Rows = 3
Columns = 7

# 29. Figure generation algorithm

処理順序を明確にする。


## Step 1

Input TIFをロードする。


## Step 2

各conditionについて対応画像を取得。


## Step 3

対象channelを抽出。


## Step 4

channel共通B&Cを適用。

pixel valueそのものは変更せず、

display mappingとして

display = clamp(
    (pixel - min) / (max - min),
    0,
    1
)

を計算。


## Step 5

LUTを適用しRGBへ変換。


## Step 6

Mergeの場合、

各channelのRGB結果を加算またはscreen-type compositeする。

基本はImageJ CompositeImageと同等のadditive RGB mergeを使用。


RGB:

R = min(255, sum(R_channel))
G = min(255, sum(G_channel))
B = min(255, sum(B_channel))


## Step 7

必要ならscale barをセル内へ描画。


## Step 8

全セルをCanvas上へ配置。


## Step 9

cell間gapを追加。


## Step 10

Row / Column label用の領域を追加。


## Step 11

Graphics2Dでlabelを描画。


## Step 12

最終RGB ImagePlusを作成。


## Step 13

Fiji上で結果を表示。


## Step 14

ユーザーがSave TIFFを実行。


# 30. 非破壊処理

非常に重要。

元画像は変更してはいけない。

以下を禁止：

- 元ImagePlusへsetMinAndMaxを恒久適用
- 元pixel値の変更
- 元LUTの変更
- 元画像へのoverlay burn-in


必ずduplicate/copyした画像に対して処理を行う。


# 31. Scientific image integrity

Brightness / Contrastは

channel単位で全condition共通

であることをUI上でも明示する。


例：

`Brightness & Contrast settings are applied identically to all conditions for each channel.`


個別画像ごとのcontrast編集機能は作らない。

# 35. Error handling

以下をチェックする。


### No images

`No input images selected.`


### channel mismatch

画像によってchannel数が異なる場合：

`Channel count differs between input images.`


どの画像が異なるか表示。


### image size mismatch

width / heightを表示して警告。


### invalid B&C

Min >= Maxの場合：

`Minimum intensity must be smaller than maximum intensity.`


### invalid scale

pixel size <= 0の場合：

`Pixel size must be greater than zero.`


### insufficient grid

condition/channel数がGridに入らない場合：

`Grid dimensions do not match the selected channels and conditions.`

# 42. 特に重要な実装方針

このプラグインは単なる画像montageではない。

中心となるデータ構造は

Condition × DisplayChannel

とする。


DisplayChannelは以下のいずれか：

SingleChannel
MergeChannel


SingleChannel：

- source channel index
- B&C
- LUT
- invert


MergeChannel：

- 複数SingleChannelへの参照


これをFigureConfigurationから描画する。


また、

Brightness & ContrastはCellではなくChannelConfigに所属させる。

これにより、

「異なるconditionで異なるcontrastが誤って適用される」

ことを構造的に防止する。
